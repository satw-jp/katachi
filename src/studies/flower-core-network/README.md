# 花芯をつなぐ — Flower Core Network

## Question

花を一つずつ読める状態を保ったまま、花芯の裏側だけをなるべく細くつなぎ、一体でプリントできる形へできるか。造形方向に対して、内部サポートが生じにくい経路と断面はどんな見た目になるか。

作者の問い（2026-08-09）:

> 花芯同士をなるべく細く繋いで内部にサポートが発生しないような形状について考えたい
>
> 必要であれば別研究へ移行してよい

作者による形の訂正（2026-08-09）:

> 想定したのは今までと同じように球体などの閉じた立体に対して花を配置して中心方向に茎のようなものがあつまっていくものだった

既存案についての判断（2026-08-09）:

> 今作ったものも見た目は悪くなかったので残しておいてほしい

## Observation

- 2026-08-09: Flower Packing の固定配置から花芯を取り出し、最小全域木と短い追加辺で必ず一群になる接続graphを作った。同じ上・横・下の7花パッチを、最短直線・表面葉脈・造形アーチの閉じたmeshとして並べられる。
- 2026-08-09: 円断面と、造形方向へ縦を向けた菱形断面を切り替えられる。根元は太く中央は細く、枝は花芯の外面ではなく裏側から始まる。
- 2026-08-09: 赤い下面はオーバーハング角による速い比較であり、実際のサポート量ではない。粗い層占有による開始領域と最長支持なし距離も別に表示し、実スライサー判定と混同しない。
- 2026-08-09: 全球は選んだ一経路を同じfieldへまとめ、一体成分・閉面・最小径が通った時だけSTLを保存できる。support-free と強度はまだ言えない。
- 2026-08-09: 設計初期値の枝中央1.2mmは粗い比較meshでは枝を取りこぼした。見かけ上だけ接続済みにせず、初期表示を中央1.6mm・根元2.4mmへ置き、細くするほど必要mesh解像度を上げる。0.8mmまで試せるが、一体mesh検査を通らなければSTLは保存できない。
- 2026-08-09: ブラウザで球の上・横・下と外・内・横、円・菱形を切り替えた。球の下を横から見ると枝と輪が最も直接読め、球の上を内から見ると赤い危険下面が花芯裏と枝に現れた。外／内は観察場所の法線へ同期し、三案は同じ画面方向を保つ。
- 2026-08-09: 初期の全球造形アーチは51花・65枝・15輪、解像度128で保存mesh 1成分・閉面・最小径1.6mmを通った。一方、粗い層支持推定は危険下面5078mm²、開始領域77、最長支持なし22.9mmで仮許容8mmを超えた。一体STLにはできるが内部サポート0とはまだ言えない。
- 2026-08-09: 作者の意図は、表面の花芯同士を横につなぐ網ではなく、球体などの閉じた立体に花を配置し、各花芯の裏から茎が中心方向へ集まる形だった。初期表示を放射状の中心茎へ訂正した。先に作った表面葉脈の見た目も判断対象として残し、「表面を横につなぐ別案」から7花三案へ戻れる。
- 2026-08-09: 51本の放射茎は解像度128では根元を2か所取りこぼして3成分になった。解像度144では51花・51茎・共有中心が1成分かつ閉面になったため、中心茎の初期値を144へ上げた。

## Hypothesis

- 表面葉脈は外から最も隠れやすいが、球の下側では造形方向に対する危険面が増える。
- 造形アーチは水平橋を短くできる一方、高さを上げすぎると花間の穴へ現れ、花より支柱が先に見える。
- 菱形断面は円より最下面が一点から始まるため積層には有利かもしれないが、角が造形理由ではなく装飾に見える可能性がある。

# S-rings — 輪の手 (T8)

## Question

球の上に「単位」という階層を足すと、何が変わるか（RESEARCH.md v5 Y7 補正:
「穴を持つ単位を下から積む」「単位間の関係のトポロジー」）。具体的には:

- 輪（球の鎖）は、つまみで不揃いに（ふわつきをもって）生めるか。均質な輪は
  死ぬ、という作者の観察（3rings の分析）は再現できるか
- 輪を単位として掴み、動かし、絡ませる手は成立するか
- 「いま何のトポロジーができているか」を道具が正直に言えるか（計器の思想の、
  力学から位相への拡張 — 絡み数 = Gauss linking number）

## Setup

`src/studies/rings/` に自己完結。`rings.html` から起動。

- **場の定義は S1 と同じ**: `cloud-sculpt/field.ts` の `Ball`・`fieldSdf`・`smoothMin` を
  そのまま import（コピーしない）。レイマーチ描画・CPU ピッキングも S1 のコード
  （`cloud-sculpt/shaders.ts` の `MAX_BALLS`、`cloud-sculpt/picking.ts` の
  `raymarchField`）を再利用。選択の可視化だけ、単一球のハイライトから
  「輪に属する全球をハイライト」に一般化した専用シェーダ（`shaders.ts`）に
  差し替えている
- **単位の階層** (`ring.ts`): `RingRecipe`（中心・軸・半径R・節数n・球の太さr・
  太さのふわつきwobbleR・位置のふわつきwobblePos・シード）から
  `generateRingBalls()` が決定的に球を並べる。ふわつきは節ごとに
  半径方向・軸方向の位置ジッタと球半径ジッタの3種（`makeRng` の同じ乱数列から
  seed 決定的に消費）
- **輪の履歴** (`history.ts`): `addRing`/`moveRing`/`rotateRing`/`duplicateRing`/
  `removeRing`/`setK`/`clear`。すべて引数から結果が決定的に再現できる
  （`moveRing` は移動量 dx/dy/dz、`rotateRing` は軸・角度・ピボットの絶対値、
  `duplicateRing` はオフセットベクトル — cloud-sculpt の `moveBall` が
  絶対座標を記録するのと同じ思想を、複数球のグループに拡張）
- **単位の手** (`main.ts`): 球をクリック→その球が属する輪を選択。選択中に
  ドラッグすると、パネルの「移動モード/回転モード」に従って輪全体を平行移動
  または回転（回転はカメラの up 軸まわり、輪の中心をピボットに、水平ドラッグ量
  に比例）。数値ボタン（X/Y/Z ±15°）でも回転できる。複製ボタンは輪の半径×1.6
  だけ X 方向にずらした複製を生む
- **絡み数の常時表示** (`linking.ts`): 下記「絡み数の式」参照。輪の全ペアに
  ついて画面操作のたびに再計算し、一覧表示。深いめり込み（融合）警告も
  同時計算
- **出口**: 「S1 レシピで書き出す」ボタンは球のリストを `addBall` の列に
  展開して cloud-sculpt の `serializeRecipe`（コピーせず import）で書き出す
  （グループ情報は落ちる、仕様どおり）。「3Dデータで書き出す」は
  `cloud-sculpt/meshExport.ts` の `buildCloudMesh` をそのまま呼ぶ
  （マーチング四面体 + 水密検査、S1・foam と同一実装）

### 絡み数の式（出典）

離散 Gauss linking number は、二つの閉じた折れ線（輪の中心線 = 節点=球中心を
順に結んだ閉ループ）の間の古典的な Gauss 連結積分

```
Lk(A,B) = (1/4π) ∮∮ (dr_A × dr_B) · (r_A − r_B) / |r_A − r_B|^3
```

を、各ループのセグメント対について中点則で離散化して計算する（`linking.ts`）。
セグメント i（A側、端点 p1,p2）とセグメント j（B側、端点 p3,p4）の寄与:

```
ds1 = p2−p1, mid1 = (p1+p2)/2
ds2 = p4−p3, mid2 = (p3+p4)/2
r = mid1 − mid2
寄与 = (ds1 × ds2) · r / |r|^3
```

を全セグメント対で足し、4π で割る。これは Gauss 連結積分の直接離散化として
標準的な手法（Ricca & Nipoti, "Gauss' Linking Number Revisited",
*J. Knot Theory Ramifications* **20** (2011)）。DNA の超螺旋計算分野では
Klenin & Langowski（*Biopolymers* **54** (2000)）のセグメント対ごとの厳密立体角式
がより精度が高いとされるが、本 Study の輪は節数が少なく（n≈6〜40）
どちらの方式も O(1/n²) 誤差を持つため、実装と検証が単純な中点則を採用した
（理由は README に残す、という AGENTS §5 の方針に従う）。

**検証**（実装前、scratchpad の使い捨てスクリプトで確認。アプリには同梱していない）:
既知の Hopf link（単位円2つを鎖のように貫通させた配置）で、節数を増やすと
|Lk| → 1.0000 に収束（n=64 で 1.0016、n=256 で 1.0001）。片方のループの向きを
反転すると符号がちょうど反転する。離れた円・同一平面上で並べた円は Lk = 0.0000。
本 Study の実際の輪相当の低節数（n=6〜24）でも、絡んだ配置は整数 1 から
最大 ±0.22 程度の誤差に収まる（n=6: 1.2164、n=24: 1.0115）— 「絡み1/0」の
四捨五入表示には十分な精度と判断した。

**融合警告のしきい値**: 異なる輪に属する球のペアで `(半径和−中心間距離)/小さい方の半径`
が 0.55 を超えたら「深いめり込み」と表示する。材料・印刷公差の根拠は無く、
第一稿のヒューリスティックとして README に明記する（AGENTS §6: 断定しない）。

## Observation（2026-07-11・実装直後の実測）

- **2026-07-17（T16 UI部品移行）**: Version / UpdatedAt 行を共通部品へ移し、DOM・文言・配置を維持した。

- **2026-07-17（T16 共通基盤移行）**: 実座標クリックで輪単位の選択色を確認し、実座標ドラッグ後も絡み実測と履歴が更新された（約60fps）。入力座標と描画ループの骨格だけを共有化し、輪・絡み計器の意味は変えていない。

- 初期状態（起動時に自動で生成される2輪、輪2は輪1をくぐる配置）で
  絡み数は「輪1と輪2: 絡み 1 (実測 1.029)」と正しく表示された
- 輪1を実座標ドラッグで輪2の外へ移動すると、絡み数は即座に
  「絡み 0 (実測 0.000)」に切り替わった。デバッグハンドル経由で
  `moveRing(2, 10,0,0)` → 離す→ `moveRing(2, -10,0,0)` で元の位置に戻すと
  絡み数は移動前と同じ 1.0294845784665179 → 1.0294845784665183
  （浮動小数点誤差レベルで一致、往復の可逆性を確認）
- 輪を複製すると新しい輪が追加され、3輪の全ペア絡み数が自動で一覧に増えた
  （輪1-輪2: 絡み1、輪1-輪3: 絡み0、輪2-輪3: 絡み-1 — 符号違いも複製の
  幾何学的な向きの違いとして自然に出た）
- 輪の削除・S1レシピ書き出し→S1での再現・履歴 export→import の往復は
  すべて実座標クリックまたはデバッグハンドル経由で検証し、期待どおり動作
- 応答実測: 通常のブラウザプレビューで ~60fps（自動化検証環境の一部では
  requestAnimationFrame が間引かれ ~0/1fps と表示されたが、これは
  cloud-sculpt・foam でも同一環境で同じ現象が出ており、本 Study 固有の
  問題ではないと判断した）
- 球28個・輪2個の状態でメッシュ検査（解像度64）: 三角形18,176枚、
  水密OK（開いた辺0・非多様体辺0）

- **2026-07-11（監査・Fable）**: 独立検証。絡み数の実測 = 初期の絡んだ2輪で 1.0295→丸め1、
  輪2を+10移動で 0、戻すと 1.0295 に完全復帰（浮動小数点まで一致 = 決定性）。moveRing 2発を含む
  履歴の export→import で球・グループとも完全一致。メッシュ 53,488 三角形・水密 OK。
  見た目も 3rings の語彙（不揃いの節・柔らかい絡み）に近いことをスクリーンショットで確認。合格。
  ※監査中に一度「絡み数が null になる」と誤診した — 原因は監査側が moveRing に誤った引数型
  （オブジェクト）を渡し NaN で状態を汚したこと。デバッグハンドルの引数は (ringId, dx, dy, dz)。

- **2026-07-11（作者実機で発見 → 修正）**: 「輪をつかんで少し動かすと遠くに行ってしまって戻ってこない」。
  原因は二重: ①移動ドラッグの平面を毎フレーム「輪のいまの中心」で張り直していたため、
  直前の移動が次の交点計算に混入して差分が指数的に増幅（S1 は絶対座標記録なので無事、
  輪は差分記録でこの罠を踏んだ）②基準点が球の表面にあり、ドラッグ面に乗っていないため
  初動で面への投影ジャンプ（約一球径）が入る。修正 = 平面は掴んだ瞬間に固定＋基準点を面上に投影。
  検証（実 PointerEvent 列）: 往復ドラッグの残留ズレ 0.00e+0、片道60px→0.478ユニット（比例・暴走なし）。
## Hypothesis

- 「輪」という最小の単位（球の鎖）だけで、既存の3rings的な絡み表現が
  最短距離で再現できた。作者の欲望（Y7補正: 単位間の関係のトポロジー）は
  「単位を選ぶ・動かす・絡み数を見る」という3操作の組み合わせで、
  複雑な専用UIを作らずとも試せる状態になっていると考える
- ふわつき（wobbleR/wobblePos）は「均質な輪は死ぬ」という作者の直感を
  そのまま数値化した最小の実装。今回は視覚的に不揃いさが出ることのみ確認し、
  「生命感」の判定は作者の視覚確認に委ねる
- 絡み数の常時表示は、力学の計器（余白の推定）と同じ設計思想
  （正直に・限界を明記して）が位相の指標にもそのまま転用できることを示した

# Hikari × Ambient — 2026年8月 作品化スケジュール

Status: active
UpdatedAt: 2026-08-01

## 今月の成果

今月はHikariをネイティブアプリ化しない。透明形状・自然光・形態変形とAmbientの音を一つの時間作品としてまとめ、8月末までに応募可能な映像と資料を揃える。

主成果物は60〜120秒の本編映像とする。Web版は観察・再現・補助デモ、Blenderは選んだカットの検証と仕上げに使う。

## 制作前ゲート

粗いテイクへ進む前に、代表ケースを一つ固定して次を確認する。

- MPMの開始、形状変化、採用、`.hkr`保存と再読込が通る。
- 採用後の球プロキシはシミュレーションを再実行せず、履歴から同じ形を復元する。
- 黒い透明部が暗い背景を正しく透過した結果か、未解決経路・TIR・数値境界の破綻かを区別する。
- 影の外に説明できない集光が出ない。黒画面、面状の黒化、極端な白飛び、点滅がない。
- 作品用の`筆跡`表示を使う場合も、元の影と到達光から生じていることを確認する。v0.29.3の島状・網状の試作だけを「手跡の光」として完成扱いせず、保存した実形状から一つの弧または連続する稜線が出ることを粗い本編のゲートにする。
- MacとWindowsで作品の主要現象が同じ意味に見える。画素一致は要求しない。

MPMは既存Studyを再利用し、Hikariへ低頻度の粗い球プロキシを渡す。今月は連続表面再構成、任意深度媒体、MPM自体の大規模改修を行わない。

## 8月1日〜7日 — 代表テイクを作る

1. 制作前ゲートを通す。
2. 初期形状、採用するMPM変形、代表視点、東京日時、外側／内包材料を一組固定する。
   最初の粗い本編は一内包でもよいが、実作との対応を示す代表静止画として三内包ケースを同時に準備し、
   個数・大きさ・位置・seed・壁厚を`.hkr`へ固定する。実装が間に合わない場合は未実装を明記し、画面合成で増やさない。
3. Ambientを「静かな初期」「流動」「集光して落ち着く」の三状態へ絞る。
4. 形、光、音の変化点を60〜120秒の一本の時間線へ置く。
5. MacまたはWindowsの画面収録で粗い本編を最低一本作る。
6. 同じ`.hkr`、MPM採用形状、Ambient設定、使用commit、収録日を保存する。

粗い本編は画面収録でよい。作品版で解像度や時間精度が不足した場合だけ、固定FPSでカメラ・形・光の時刻を
1フレームずつ進めるPNG連番のOffline / Batch Renderを次段階として実装し、Premiere等で音と合成する。
リアルタイムの表示fpsを連番の時間軸へ混ぜない。

完了条件は、完成度ではなく最初から最後まで作品として見られる一本が存在すること。

## 8月8日〜14日 — 粗編集と必要最小限の修正

- 黒画面、ちらつき、白飛び、形の破綻、音割れだけを優先して直す。
- 変形速度、カメラ周回時間、音の密度を粗編集から調整する。
- 60〜120秒の粗編集と15〜30秒の予告編候補を作る。
- タイトル候補、一文説明、短いステートメントを書く。

新機能は粗いテイクで作品成立を妨げたものに限定する。

## 8月15日〜21日 — 作品版を固定

- 本編構成と音を固定する。
- 代表静止画を4〜6枚選ぶ。
- `.hkr`、形状履歴、Ambient設定、commit、近似・制限事項をまとめる。
- Webデモを使う場合は公開URLと起動手順を確認する。

この週以降は方向を変えるレンダラー改修を行わない。

## 8月22日〜31日 — 応募パッケージ

- 本編60〜120秒、予告編15〜30秒、静止画4〜6枚
- 作品タイトル、200〜400字概要、ステートメント、プロフィール
- 技術・展示方法、必要機材、音響条件、近似・非物理性の注記
- Webまたは映像リンク、制作年、使用技術、再現用ケース

応募候補は最新の締切と形式を再確認して1〜3件へ絞る。募集に合わせて作品を作り直すのではなく、8月31日時点でローリング募集や次回募集にも出せる完成パッケージを残す。

## 今月やらないこと

- Windowsネイティブ描画、ネイティブ光学計算
- 汎用レンダラー化、完全な連続MPM表面、任意深度の多重媒体
- 大規模な部屋・窓・建築スケール実装
- 応募先ごとの過剰な個別カスタマイズ

判断に迷った場合は、機能数ではなく本編映像が一本完成するかを優先する。

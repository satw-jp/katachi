## 1. 結論

現在の手動造形を正本として残し、その上に、引力・斥力などで球の配置だけを整える**非破壊の補助機能**を追加できる。

実装の中心方針は次の四点とする。

1. Cloud Sculpt のメイン造形は今の簡潔さを維持する。
2. 自動調整は、作者が明示的に開く「追加機能」の中だけで動かす。
3. 計算結果はまずプレビューし、「この配置を採用」するまで手動造形の正本を変更しない。
4. 既存 Study を一つの巨大な画面へ合体させず、関係を整理して到達可能にし、安定した計算だけを共有する。

この補助機能は「形を自動生成するAI」ではない。作者が作った形の意図を残したまま、重なり、まとまり、間隔、重力への応答を別の視点から試す道具である。

## 2. 背景と確認できた現状

### 2.1 手動造形

**Observed:** Cloud Sculpt は `Ball[]` を形の基本単位とし、次の操作を履歴へ保存している。

- Grow / Reroll
- 球の追加・削除
- 球の移動
- 半径の変更
- count、radius、spread、k、seed の変更
- clear

履歴を先頭から replay すると同じ形が再現される。したがって、手動で作られた球の配置と操作履歴が現在の正本である。

### 2.2 既存の力学・自動配置に近い機能

**Observed:** Sag の液体側計算には、現在位置から近傍を求め直しながら働く斥力と凝集力がすでにある。

- 近すぎる球を押し戻す
- 少し離れた球を弱く引き寄せる
- 球同士の重なりを残した平衡距離を使う
- 重力と減衰によって形を落ち着かせる
- 同じ入力から同じ結果を返す純粋計算である

**Observed:** MPM は Cloud Sculpt / Hikari 内にすでにプレビュー、停止、採用の流れを持つ。ただしこれは軽い配置整理ではなく、連続的な動的変形の近似である。

**Inferred:** 新しい「配置を整える」は MPM より軽く、Sag の引力・斥力の考え方に近い。ただし Sag が持つ「自重でたわむ」「液体化する」という作品固有の意味を、そのまま Cloud Sculpt の標準操作へ持ち込むべきではない。

### 2.3 既存 Study へのアクセス

**Observed:** `src/lib/studies.ts` には、現在11件の Study が正式な一覧として定義されている。

**Observed:** Cloud Sculpt の UI では `Study 一覧` と `Interior Growth` のリンクを一度作成しているが、後段の `replaceChildren` によるUI再構成で表示から外れている。また「ほかの実験」は一部のリンクだけを手動で追加しており、全11件を反映していない。

**Inferred:** 機能そのものが消えたのではなく、入口が複数の手書きリストへ分散し、正式な一覧と表示がずれている。

## 3. 機能の再分類

機能名や実装元ではなく、「作者が形に対して何をするか」で分類する。

| 制作上の役割 | 機能・Study | 形への作用 | Cloud Sculpt での扱い |
|---|---|---|---|
| 手でつくる | Cloud Sculpt | 球を直接追加・移動・変更する | 常時表示するメイン機能 |
| 配置を整える | 新しい軽量配置調整 | 個数・半径を保ち、位置だけを調整する | 折りたたまれた追加機能 |
| 力で変形する | Sag / MPM | 重力、柔らかさ、動力学によって形を変える | 追加機能から到達。固有UIは維持 |
| 分析する | Gravity | 応力や支持を可視化し、形は変更しない | 分析機能として明示 |
| 場を派生させる | Foam | 同じ球群を別の場・セル表現へ変換する | 別 Study として開く |
| 内部・表面をつくる | Pack / Skin / Interior Growth | 内部、表面、空隙へ新しい構造を作る | 別 Study として開く |
| 単位・軌跡からつくる | Rings / Tangle | 球以外の制作単位や軌跡から形を作る | 別 Study として開く |
| 原理を比較する | Hitsuji | 固定した対象へ異なる原理を作用させる | 比較 Study として開く |

### 再編の境界

- Study 固有の画面、状態、履歴、renderer は統合しない。
- 二つ以上の用途で安定して使える純粋計算だけを `src/lib` へ昇格させる。
- Cloud Sculpt は万能編集画面にしない。
- 「別 Study を開く」と「現在の形を渡して開く」を混同しない。形の受け渡しが未実装なら、その事実をUIに表示する。

## 4. 目標となる画面構造

Cloud Sculpt のメイン画面には現在の直接操作を残す。追加機能は初期状態で閉じる。

```text
KATACHI
├─ 形をつくる                         常時表示
│  ├─ Grow / Reroll
│  ├─ 個数・大きさ・広がり・接続
│  └─ 選択、移動、半径、追加、削除
│
├─ 追加機能                           初期状態では閉じる
│  ├─ 配置を整える                    Cloud Sculpt 内の非破壊機能
│  ├─ 力で変形する                    Sag / MPM
│  ├─ 分析する                        Gravity
│  └─ 内部・表面・別原理からつくる    関連 Study への入口
│
└─ すべての Study を見る              正式な launcher への入口
```

Hikari の光学操作は現在のレイヤーを維持する。「配置を整える」は光学現象ではなく形態制作なので KATACHI 側へ置く。

既存の MPM 操作は最初の段階では移動・削除しない。KATACHI 側から同じ機能へ到達できる導線を追加し、Hikari 側の既存操作との重複は、利用状況を確認した後に整理する。

## 5. 「配置を整える」の操作仕様

### 5.1 基本原則

- 入力は現在の `Ball[]` とする。
- 出力は同じ長さ、同じ順序、同じID、同じ半径の `Ball[]` とする。
- 初期版で変更してよいのは `x / y / z` だけとする。
- 計算中の配置はプレビュー状態として保持する。
- 「採用」前の履歴、保存データ、Blender書き出し対象は変更しない。
- 同じ入力と設定から同じ結果を返す。

### 5.2 作者に見せるパラメータ

物理係数をそのまま並べず、造形上の意味に翻訳する。

| 表示名 | 内部で制御するもの | 造形上の意味 |
|---|---|---|
| まとまり | 中距離の凝集力 | 離れかけた部分を一つの塊として保つ |
| 押し戻し | 短距離の斥力 | 重なりすぎや局所的な潰れを減らす |
| 元の形を残す | 初期位置への復元力 | 手で作った輪郭や構成を保持する |
| 重力 | 下向きの外力 | 床や支持方向へ形を落ち着かせる |
| 選択部分を固定 | 固定点 | 作者が残したい中心や端部を動かさない |

初期表示では、次の操作だけでもよい。

- `少し整える`
- `落ち着くまで進める`
- `この配置を採用`
- `元に戻す`

詳細なパラメータは二段目の「調整」内へ置く。

### 5.3 力の構成

各球に働く力を次の和として扱う。

```text
合力
= 近距離斥力
+ 中距離凝集力
+ 元位置への復元力
+ 任意の重力
+ 任意の固定条件
```

#### 近距離斥力

球が深く重なったときに押し戻す。ただし、球同士が接するだけの距離まで分離させない。

Cloud Sculpt の滑らかな外形は、球が適度に重なることで成立している。平衡距離は `r_i + r_j` より小さくし、現在の smooth-min が必要とする重なりを維持する。

#### 中距離凝集力

局所的に近い球だけを引き寄せる。遠く離れた部分同士まで一斉に引き寄せると、形全体が一点へ潰れるため、作用距離を限定する。

#### 元位置への復元力

プレビュー開始時の位置を rest position として保存し、そこから離れすぎた球を戻す。これが「自動生成」ではなく「手動造形の補助」であることを支える中心的な力となる。

#### 重力

初期状態はOFFとする。ONの場合だけ、床または指定した方向を使う。床との接触や沈み込みは Sag の作品固有値をそのまま流用せず、配置調整用の契約を別に定義する。

### 5.4 ドリフトと固定

固定点、重心補正、重力が同時に働いたときの優先順位を次のように固定する。

| 条件 | 固定点 | 重心補正 |
|---|---|---|
| 重力OFF・固定点なし | なし | 全球で入力時の3軸重心を維持する |
| 重力OFF・固定点あり | 固定球を毎stepでrest positionへ厳密に戻す | 行わない |
| 重力ON | 指定されていれば厳密固定する | 行わない |

初期版では、固定点と重心補正を同時に解こうとしない。固定されていない球へ重心差を押し込むと、固定点の周囲で作者が意図しない移動が生じるためである。

UIで選択できる固定球は一つから始めてよい。ただし計算設定は将来の複数固定に備えて `fixedBallIds` の集合として受け取る。重力ON時に水平方向だけ重心を保つ拡張は初期版へ含めない。

### 5.5 「落ち着くまで進める」の停止条件

`落ち着いた` を見た目や実装者の判断で決めず、次の契約で判定する。

```ts
type SettleCriteria = {
  maxSteps: number;
  displacementEpsilon: number;
  stableStepsRequired: number;
};

type SettleTermination =
  | "settled"
  | "max-steps"
  | "stopped-by-user"
  | "invalid";
```

初期値は次を出発点とする。

```ts
const DEFAULT_SETTLE_CRITERIA: SettleCriteria = {
  maxSteps: 600,
  displacementEpsilon: 1e-4, // shape unit / step
  stableStepsRequired: 12,
};
```

各stepの全球について `distance(previous, current)` を測り、その最大値が `displacementEpsilon` 未満の状態が `stableStepsRequired` 回連続したときだけ `settled` とする。

- `maxSteps`へ達した場合は `max-steps` と表示する。結果はpreviewとして残すが、「落ち着いた」とは表示しない。
- 作者が停止した場合は `stopped-by-user` とし、その時点の有限なpreviewを残す。
- 座標、速度、力のいずれかに `NaN` / `Infinity` が出た場合は直ちに停止して `invalid` とする。invalidなpreviewは採用できない。
- 実行はフレームへ分割し、各フレームの開始前に停止要求を確認する。
- `少し整える` は収束判定ではなく、固定数のstepだけ進める操作とする。初期値は12 stepとし、作者向けUIにはstep数を露出しない。

これらの数値はR2cの固定ケースとR3の実機確認で較正できる。ただし、停止理由の種類と判定方法は変更しない。

## 6. 非破壊プレビューと採用

### 6.1 状態

```ts
type ShapeRevision = number;

type ArrangementPreview = {
  sourceRevision: ShapeRevision;
  sourceBalls: Ball[];
  previewBalls: Ball[];
  settings: ArrangementSettings;
  stepCount: number;
  status: "idle" | "previewing" | SettleTermination;
};
```

型名と詳細は実装時に確定する。重要なのは、正本の `state.balls` と preview を同じ配列として扱わないことである。

`sourceRevision` は配列hashではなく、Cloud Sculptの正本球が変更されるたびに増える**ランタイム上の単調増加カウンタ**とする。

- Grow / Reroll、追加、削除、移動、半径変更、clear、読込／replayによる球配列の置換、配置採用、配置採用の取消で一回増やす。
- 球を変更しないカメラ操作、選択、Hikari設定、preview計算では増やさない。
- count、seed、spreadなどの入力欄だけを変更し、まだGrowしていない場合も増やさない。
- 複数の `moveBall` からなる配置採用は、ランタイム上では一つの変更として一回だけ増やす。
- preview開始時の値を保存し、採用時の現在値と一致しなければ採用を拒否してpreviewを破棄する。
- counter自体は保存schemaへ追加しない。再読込をまたぐpreviewは存在しないため、ページ開始時の初期値は任意の一定値でよい。

これにより、preview開始後に正本が別経路から変更された場合のstale adoptionを、浮動小数点hashや配列全走査なしで防ぐ。

### 6.2 編集との関係

- 球の選択・選択解除、カメラ操作、Hikariの観察操作ではpreviewを維持する。
- 球の選択だけでは固定状態を変更しない。選択と `選択部分を固定` の指定は別操作とする。
- 配置調整パラメータを変更した場合は、正本と `sourceBalls` を維持し、途中のpreviewを捨てて `sourceBalls` から新設定で再計算する。
- 固定対象を変更した場合も設定変更として扱い、途中状態から続けず `sourceBalls` から再計算する。
- 正本球の移動、半径変更、追加、削除、Grow / Reroll、clear、読込／replayではpreviewを破棄する。
- count、seed、spreadなどの形態入力欄だけの変更は、正本球が変わらない限りpreviewを破棄しない。Growを実行した時点で破棄する。
- preview 中であることを、色だけに依存せずラベルで表示する。

### 6.3 反復操作の継続規則

- 同じ `ArrangementSettings` で `少し整える` を再度押した場合は、現在の `previewBalls` からさらに12 step進める。
- 初回だけ `sourceBalls` から開始する。連打のたびにsourceへ巻き戻さない。
- 同じ設定で `落ち着くまで進める` を押した場合も、現在のpreviewから継続する。ただし連続安定stepのカウントはその実行開始時に0へ戻す。
- 設定または固定対象を変更した場合は、`previewBalls = sourceBalls`、`stepCount = 0`、安定step数 = 0へ戻してから新設定で再計算する。
- `ArrangementSettings` の比較には、UI表示文字列ではなく、範囲制限と既定値適用後の正規化済み数値および `fixedBallIds` を使う。
- `sourceRevision` が一致しない場合は継続も再計算も行わず、previewを破棄する。

### 6.4 採用方法

初期実装では新しい履歴 op を追加せず、位置が変わった各球について既存の `moveBall` を記録する。

微小な数値差を履歴へ入れないため、採用対象を次で限定する。

```ts
const ADOPTION_EPSILON = 1e-5; // shape unit

distance(sourceBall.position, previewBall.position) > ADOPTION_EPSILON
```

比較は距離の二乗で実装してよいが、意味は上のユークリッド距離と一致させる。閾値を超える球が一つもない場合は履歴を追加せず、「採用する変化はありません」と表示する。

理由:

- 既存の `.hkr` / recipe 契約を変更しない。
- 球のID、個数、半径を維持できる。
- replay 後に計算を再実行せず、作者が採用した結果そのものを復元できる。
- solver の将来変更によって過去作品の形が変わらない。

40球程度では保存上の履歴件数の増加は許容できる。実使用で履歴が読みにくくなる場合にだけ、複数移動をまとめる新しい保存 op を別契約として検討する。

### 6.5 採用トランザクションと取消

**Observed:** 現在の Cloud Sculpt には一般的な Undo / Redo 機構がない。そのため、存在しないUndoグループを前提にしない。

R4では、配置の採用をランタイム上の一つのトランザクションとして扱う。

```ts
type ArrangementAdoptionTransaction = {
  sourceRevision: ShapeRevision;
  moves: Array<{
    id: number;
    before: { x: number; y: number; z: number };
    after: { x: number; y: number; z: number };
  }>;
};
```

- 全moveを事前検証してから、一まとまりとして履歴へappendする。
- 一件でもID不一致や非有限値があれば、どのmoveもappendしない。
- 採用直後には `直前の配置採用を取り消す` を表示し、同じトランザクションの `before` を一括適用する。
- 取消も保存上は既存 `moveBall` の集合として記録し、schemaを追加しない。
- 別の手動造形、読込、Grow、別の配置採用が行われたら、専用取消の対象を失効させる。
- ページ再読込後の一般Undoは初期版の対象外とする。

将来、Cloud Sculpt全体へUndo / Redoを導入する場合は、このトランザクション境界を一般のhistory groupへ昇格させる。保存schemaへgroup情報を入れるかどうかは、その段階で別途判断する。

## 7. 計算実装の境界

### 7.1 推奨構造

```text
src/lib/ballRelaxation.ts
  純粋な球配置計算
  UI、DOM、renderer、履歴、Hikariを知らない

src/studies/sag/deform.ts
  Sag固有の重力、床、柔らかさ、液体化の意味を与える

src/studies/cloud-sculpt/arrangement.ts
  Cloud Sculpt固有の設定名、重心維持、preview用の変換を行う
```

実際のファイル名は実装レビューで調整できる。

### 7.2 抽出手順

1. 現在の Sag に固定ケーステストを追加する。
2. 現在位置から近傍を求める pair force の核だけを純粋関数として抽出する。
3. Sag の出力が抽出前と変わらないことを確認する。
4. Cloud Sculpt 用 wrapper から、重力OFF、rest保持ONの設定で利用する。

Sag の液体計算全体を直接呼び出さない。Sag の定数には床への沈み込み、液体用重力、二段減衰など固有の意味が含まれるためである。

### 7.3 初期性能方針

現在の最大球数は256である。初期版は結果の正しさを優先し、球数が少ない通常ケースでは全ペア計算を許容する。

性能目標:

- 40球の一回のプレビュー更新: 8ms以内を目標
- 128球: 16ms以内を目標
- UIを占有する長い反復は一度に実行せず、フレームへ分割する
- 128球以上で目標を超える場合、空間ハッシュによる近傍探索を追加する
- M4 MacBook Air で操作時の描画と入力を止めない

数値は物理精度の保証ではなく、対話性の受け入れ目標である。

## 8. 既存機能への入口の再設計

### 8.1 正本

Study のID、表示名、URL、研究順は `STUDY_CATALOG` を表示の正本とする。Cloud Sculpt 内に全リンクを再記述しない。

### 8.2 関係性の表示

Cloud Sculpt から見た関係だけを、小さな Instrument 固有の分類として持つ。

```ts
type CloudSculptRelation =
  | "analysis"
  | "deformation"
  | "derived-field"
  | "interior-surface"
  | "unit-trajectory"
  | "comparison";
```

この分類は Study の新しい正本ではなく、Cloud Sculpt から見た制作上の関係を表示するための索引である。登録したIDが `STUDY_CATALOG` に存在することをテストする。

### 8.3 表示する接続状態

各入口には、必要に応じて次の状態を表示する。

- `この画面で使える` — Cloud Sculpt 内に統合済み
- `現在の形を渡せる` — recipe または明示した変換で接続済み
- `別の実験として開く` — URLだけを共有し、状態は渡さない
- `準備中` — 関係はあるが、安全な受け渡し契約が未実装

単にリンクがあることを「統合済み」と呼ばない。

## 9. 実装段階

各段階は単独で確認・rollbackできるようにする。

実装依頼では R1〜R4 を一括変更にしない。`R1 → R2a → R2b → R2c → R3 → R4` の順に進め、各段階を独立したcommitとして、テスト結果と確認記録を添える。特にR2bの計算共通化とR3のUI変更を同じcommitへ含めない。

### R0 — 現在のR0.5作業を確定する

**目的:** 未コミットの光学イベント契約実装と本機能の変更を混在させない。

- 現在進行中のR0.5実装をテストし、独立したcommitとして確定する。
- 本計画の実装はその後のcommitから始める。
- 光学イベント、receiver transport、shader の変更を本計画へ含めない。

**完了条件:** 本計画の着手点となるcommitが一意に記録されている。

### R1 — 入口だけを直す

**目的:** 失われた機能へのアクセスを先に回復する。

- Cloud Sculpt の手書きStudyリンクを整理する。
- `Study 一覧` を常時到達可能にする。
- 全11件を `STUDY_CATALOG` から表示する。
- 本書 §3 の関係別にまとめる。
- 形の受け渡しがないStudyには「別の実験として開く」と表示する。

**変更しないもの:** solver、球、履歴、保存形式、renderer。

**完了条件:** Cloud Sculpt と launcher から全Studyへ到達でき、表示IDがcatalogと一致する。

### R2 — 配置計算の契約と固定ケース

**目的:** UIを作る前に、計算の意味と不変条件を固定する。テスト追加、共通化、Cloud Sculptへの接続を別commitへ分ける。

#### R2a — Sagの固定ケース

- productionの計算を変更せず、Sagの代表入力と現行出力をfixture化する。
- solid、middle、liquidの各領域を最低一件含める。
- 球位置、重心、broken flag、接触／近傍関係を記録する。
- 固定ケース生成時のcommitと実行環境を記録する。

**完了条件:** テスト追加だけのcommitで、現行Sagがpassする。

#### R2b — pair force核の抽出

- 現在位置から近傍を求めるpair forceの核だけを純粋関数として抽出する。
- Sag固有の重力、床、液体用定数、反復スケジュールはSag側に残す。
- 可能な限りループ順、加算順、定数、反復回数を維持する。
- §10.2のSag回帰条件でR2a fixtureと比較する。

**完了条件:** 抽出commitだけを戻せる状態で、Sag回帰条件を満たす。

#### R2c — Cloud Sculpt用wrapper

- `ArrangementSettings`、`SettleCriteria`、結果型を定義する。
- 重心維持、固定点、有限値、停止理由、決定性をUIなしでテストする。
- smooth-minに必要な重なりを残す平衡距離を評価する。
- `少し整える`の12 stepと、最大600 stepのsettleをfixtureで確認する。

**完了条件:** Cloud Sculpt用計算がUIなしで検証でき、Sag固有の意味へ依存していない。

### R3 — 非破壊プレビュー

**目的:** 作者が結果を比較できる最小の体験を作る。

- KATACHIに閉じた「追加機能」を追加する。
- `配置を整える` をその中に置く。
- `少し整える`、`落ち着くまで進める`、`元に戻す` を実装する。
- preview状態を正本から分離する。
- 手動編集、Grow、読込によるpreview破棄を実装する。
- M4 MBAで操作性を確認する。

**変更しないもの:** 履歴と保存結果。

**完了条件:** previewを何度試しても、採用しない限り保存される形が変わらない。

### R4 — 採用と保存

**目的:** 気に入った配置を作品データへ確定する。

- `この配置を採用` を追加する。
- `ADOPTION_EPSILON = 1e-5` を超えた差分だけを既存の `moveBall` 履歴として記録する。
- 全moveを一つのランタイムトランザクションとして検証・appendする。
- `直前の配置採用を取り消す` を追加する。
- export → import → replay で同じ位置を復元する。
- 採用後はpreviewを破棄し、新しい正本として表示する。

**完了条件:** ID、個数、半径を保ち、位置だけが変わる。一回の採用を一回の操作として取り消せる。旧 `.hkr` も従来どおり開く。

### R5 — 既存の変形機能との接続

**目的:** 重複した機能名と入口を整理する。

- MPMをKATACHIの「力で変形する」からも利用可能にする。
- Sagは静的な導出、MPMは動的な変形、配置調整は軽量な位置整理として説明を分ける。
- Hikari側にある既存MPM入口は、利用状況を見て残すか移すか決める。
- 現在の形を別Studyへ渡す機能は、既存recipe契約が確認できた組み合わせから一件ずつ追加する。

**完了条件:** 同じ機能が別名で二重実装されず、各入口の違いが作者に分かる。

## 10. テスト計画

### 10.1 数値・契約テスト

- 同じ `Ball[]` と設定から同じ出力になる。
- 出力の長さ、順序、ID、半径が入力と一致する。
- 全座標が有限値である。
- 重力OFFかつ固定点なしの場合、重心が許容誤差内で維持される。
- 固定した球の位置が変わらない。
- 固定点あり、または重力ONでは重心補正が実行されない。
- 斥力だけを強めても、平衡時に必要な重なりが残る。
- まとまり0では遠距離の球を新しく引き寄せない。
- 0 stepでは入力と完全一致する。
- 最大変位が `1e-4` 未満の状態が12 step連続した場合だけ `settled` になる。
- 600 stepで収束しなければ `max-steps` になる。
- 停止要求は `stopped-by-user`、非有限値は `invalid` になる。
- `invalid` なpreviewを採用できない。
- cancel後に元の位置へ完全に戻る。
- 移動量が `1e-5` 以下の球には採用履歴を追加しない。
- adopt後の replay が採用時の位置と一致する。
- adoption途中の検証失敗では履歴が一件も追加されない。
- `直前の配置採用を取り消す` で、対象球すべてが採用前へ一度に戻る。

### 10.2 回帰テスト

- Sag の代表的な solid / middle / liquid ケースをR2aで抽出前に固定する。
- 以下の完全一致・数値許容差は、同一JavaScript runtime、同一backend、同一アーキテクチャ上のCPU純粋計算unit testにだけ適用する。ブラウザ、Node、CPUアーキテクチャ、GPU経路をまたぐ画像比較の許容差として流用しない。
- 同じループ順と演算順を維持できた場合は、球位置とbroken flagの完全一致を要求する。
- 関数分離によって演算順が避けられず変化する場合に限り、次の数値許容差を用いる。
  - 球位置の最大差: `1e-7` shape unit以下
  - 球位置の平均差: `1e-8` shape unit以下
  - 重心差: `1e-8` shape unit以下
  - broken flag: 完全一致
  - 接触／近傍関係: 完全一致
- 「見た目が似ている」だけでSag回帰をpassさせない。
- 旧 recipe と旧 `.hkr` が読み込める。
- 現在の手動追加、移動、半径変更、削除が変わらない。
- Hikariの光学計算と保存ケースに変更がない。
- MPMの既存preview / adoptが変わらない。

### 10.3 実画面確認

- 初回表示で追加機能が閉じている。
- 追加機能を知らない作者でも従来の手動造形を続けられる。
- preview中であることが文字で判別できる。
- 採用と取消を誤操作しにくい。
- 全11 Studyのリンクを実座標クリックで確認する。
- desktopと狭幅画面で操作が隠れない。
- M4 MacBook Airでカメラ操作と入力が停止しない。

## 11. 主なリスクと対策

### 11.1 斥力によって外形が崩れる

球を接触距離まで離すと、smooth-min の連続した外形が弱くなる。

**対策:** 平衡距離を半径和より小さくし、外形の連続性を画像と数値の両方で確認する。

### 11.2 引力によって一点へ潰れる

すべての球が相互に引き合うと、作者の構成が失われる。

**対策:** 作用距離を限定し、rest positionへの復元力を既定で有効にする。

### 11.3 自動調整が手動造形を上書きする

計算が常時走ると、作者が置いた位置が正本でなくなる。

**対策:** preview / adoptを明確に分け、自動実行を初期状態でOFFにする。

### 11.4 Sagの作品固有挙動を壊す

共通化の際に定数や反復順を変えると、Sagの既存表現が変化する。

**対策:** 抽出前に固定ケースを作り、出力を変えない小さなpure functionから移す。

### 11.5 UIが再び複雑になる

過去の機能をすべてプロパティとして並べると、メイン造形が見えなくなる。

**対策:** メイン、追加機能、別Studyの三段階に分け、詳細項目は初期状態で閉じる。

### 11.6 リンク一覧が再び古くなる

各画面でStudy名とURLを手入力するとcatalogとの差が再発する。

**対策:** 表示値は `STUDY_CATALOG` から生成し、関係分類に存在しないIDと重複IDをテストする。

## 14. 推奨する最初の実装範囲

最初のリリースは R1〜R4 に限定する。

完成像は次の通り。

1. 今までどおり手で形を作れる。
2. 必要なときだけ「配置を整える」を開く。
3. まとまり、押し戻し、元形保持による変化を非破壊で見る。
4. 良ければ採用し、違えば完全に戻す。
5. 採用直後なら、一回の採用を一回の操作として取り消せる。
6. 別の原理が必要なら、関係別に整理された既存Studyを開く。

この範囲で、手動造形の主体性を守りながら、自動配置を制作上の新しい手として追加できる。R5以降の統合は、この操作が実際の作品制作で使われることを確認してから進める。

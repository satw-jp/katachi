Recommend **Option B**, a versioned SLICE_KEY v0.2 that explicitly separates requested identity, environment compatibility and deep provenance. Preserve [v0.1 contract](SLICE_KEY_CONTRACT_V0_1.md), [generator](../../tools/slice-console/SLICE_KEY_GENERATOR.md), [Identity Lock](../../tools/slice-console/IDENTITY_LOCK.md), schemas, code and six golden fixture files unchanged. Identity Lock independently withholds a usable identity when closure is INCOMPLETE. Thus a stable request with observed file bytes remains permanently held while loader binding/parent state cannot be closed without process evidence. Those observations stay true: static DLL load intent resolved locally, actual physical bindings/initial-loader state unresolved. Their unresolved status is retained rather than rewritten to COMPLETE.

## Three independent layers and statuses
| Layer | Meaning | Generation / lookup role | Unknown handling |
|---|---|---|---|
|A REQUEST_IDENTITY|Complete versioned declaration of what FULL_SLICE is requested to execute|Only this layer forms SLICE_KEY/v0.2 request digest|Unknown critical request semantics -> REQUEST_STATUS INCOMPLETE/HOLD, no key|
|B EXECUTION_ENV_FINGERPRINT|Observed finite host/runtime/config evidence under explicit compatibility coverage policy|Separate fingerprint and comparison gate; request key match discovers candidates only|Missing required compatibility observations -> UNVERIFIED_ENV, no automatic REUSE; A may still produce a key|
|C DEEP_RUNTIME_PROVENANCE|Exact loaded DLLs, parent loader state, dynamic/transitive module set, traces|Diagnostic/forensic references only for R0.1|Remain UNRESOLVED/NOT_COLLECTED; absence alone does not block A generation or B classification|

Proposed result envelope (names are design, not existing implementation): REQUEST_STATUS COMPLETE/INCOMPLETE; REQUEST_KEY present/null; ENV_OBSERVATION_STATUS COMPLETE_WITHIN_DECLARED_POLICY/INCOMPLETE; compatibility class per comparison; DEEP_PROVENANCE_STATUS recorded independently; REUSE_ELIGIBILITY NOT_EVALUATED/HOLD/ELIGIBLE_BY_POLICY. COMPLETE_WITHIN_DECLARED_POLICY never claims full OS closure. A key cannot encode "unknown" as a substitute for required A values. B's unknown fields are tagged evidence states outside the key; equal unknown tags/digests cannot establish compatibility.
Key generation, candidate lookup and REUSE authorization are distinct. An A-complete/B-incomplete request can receive a request key and locate candidates, while REUSE remains HOLD. There is no automatic slicing fallback. A-complete is not slice success, environment compatibility, audit PASS or Print GO.

K = A key material; E = B compatibility/provenance; D = C diagnostic. Roles are assigned by a versioned route policy, never guessed from an extension or basename. A file may have separate roles: toolpath-config bytes belong to K even if its observed location is also E.

Bounded request-resource coverage specifies the requested configuration set, not "all files an OS loader might ever discover". An unsupported route or a missing declared/known-critical input is HOLD; absence of a complete runtime consumption proof belongs to B/C. This is an explicit contract boundary change. The actual operational route is **not certified A-complete or B-complete by this design**; the next pure generator uses synthetic preverified descriptors only. Selecting a production manifest/route adapter requires a separate task/review, not resumed DLL forensics.
Path strings use the route/backend's exact resolved representation; no arbitrary case folding, separator replacement or removal. Future relocation equivalence requires a new explicit policy. Sensitive A parameters need approved nonpublic identity handling; raw secrets must not appear in public keys/descriptors. Until an approved scheme exists, that request is HOLD. Fingerprint coverage describes effective inherited env only where observed; other env is OUTSIDE_DECLARED_POLICY, not proven inert.

## Canonical request contract proposal
Namespace/output: `SLICE_KEY/v0.2:sha256:<lowercase digest>`. Fixed root domain SLICE_KEY/v0.2, key_schema_version0.2, operation FULL_SLICE. Logical request sections: contracts/policies/backend_bundle, ordered inputs, profiles/mappings, engine{version,executable_sha256}, selected_request_resources, execution{typed semantic argv, bound cwd, semantic env/transport declarations}. B/C are not members of the canonical request tree.
Retain v0.1's lossless decimal strings, explicit units/tagged optional states, Unicode scalar preservation, duplicate-key rejection, fixed member names, array order and custom compact UTF8 JSON serialization. Do not reuse a v0.1 digest by deleting fields; new canonical tree/domain and independent golden bytes are required. Physical/opaque paths are explicitly typed request bindings when retained. Root completeness attestations refer only to the reviewed A coverage, not a renamed v0.1 "resources verified" flag.
Proposed environment document: versioned `EXECUTION_ENV_FINGERPRINT/v0.1`, policy identity/required-item coverage, observed values/content manifests, observation state/source/freshness and fingerprint digest. Fingerprint equality compares known identity fields under the same coverage; timestamps/paths used only as evidence cannot define equivalence. Incomplete documents may have a diagnostic document digest, explicitly non-authorizing. C references are optional separately, never appended to A bytes.

## Environment compatibility policy
Comparison relates a stored prior-run observation to a fresh current observation; a single fingerprint has no intrinsic compatibility class. Default reviewed R0.1 finite coverage requires OS/platform/arch, BambuStudio.dll, selected native/resource candidates, schema/VC/UCRT, actual Python distribution and relevant env observations above. No C requirement. Missing/unknown required B items cannot yield EXACT_ENV even if document digests match.

| Class | Criteria | Candidate/REUSE handling |
|---|---|---|
|EXACT_ENV|Same approved compatibility policy/coverage; all required B items known/fresh and their identity values equal; A key match also required separately|Can proceed to artifact/state gates. Means exact observed fingerprint within declared boundary, not byte-identical full environment|
|COMPATIBLE_ENV|All required observations known; differences allowed by explicit reviewed directional rules covering every difference, with evidence and policy version pinned|Can proceed only if explicit REUSE policy permits this class; no heuristic compatibility|
|UNVERIFIED_ENV|Missing/stale/untrusted required observation, unknown critical env classification, or a known difference without an applicable approved rule|Candidate may be shown; automatic REUSE HOLD. Equal unknown/missing observations do not permit reuse|
|INCOMPATIBLE_ENV|Known deny-rule difference (platform/arch by default, DLL SHA by default), or known A engine/input/profile/backend/policy mismatch at compatibility precheck|Reject candidate; no implicit reslice|

Evaluation order: known disqualifying A/deny difference wins INCOMPATIBLE_ENV even if other observations missing; otherwise required B gaps or uncovered differences -> UNVERIFIED_ENV; else all equal -> EXACT_ENV; else all differences explicitly covered -> COMPATIBLE_ENV. Rules are explicit, directional and not inferred transitively. Default rule set has **no** OS/runtime/Python upgrade equivalence allowlist. Such differences require a reviewed rule, or remain UNVERIFIED/INCOMPATIBLE under named deny rules; this task invents no OS/runtime compatibility evidence. An explicit request change is normally already a different lookup key, not an environment exception.
Compatibility rule updates require versioned policy identity and re-evaluation; they do not mutate stored fingerprints or keys. Revoked policy/rule -> HOLD. C evidence is never mandatory in this default R0.1 policy; a future separate policy requesting it would need explicit Author authorization and cannot silently replace this boundary.

## Future cache / REUSE safety gate
SLICE_KEY match selects a candidate **actual prior artifact**, never a promise of new output determinism. Before any future REUSE, all seven gates must pass:
1. Fresh A descriptor complete, same namespace/policy/request key; request inputs/config/backend/engine reverified from explicit evidence. No cross-version or unknown-field coercion.
2. Fresh B comparison satisfies approved compatibility policy; EXACT_ENV or explicitly allowed COMPATIBLE_ENV. UNVERIFIED_ENV never automatic REUSE.
3. Bound prior terminal Runner result is SUCCESS/execution_success=true for the exact source request/run. FAILED/CANCELLED/missing/incomplete manifest rejects; do not infer success from filenames.
4. Explicit run/artifact pointers, existence/size and fresh exact artifact SHA match pinned prior records. Never choose by name/time/latest; request key is not an artifact identifier.
5. Required artifact integrity verified (readable/complete payload and type-specific integrity). For packaged G-code retain ZIP CRC and embedded/standalone SHA equality plus context requirements. Hash agreement alone is not toolpath/audit acceptance.
6. Required audit/package state is satisfied under current versioned REUSE policy, bound to these artifact hashes. Pending/unsupported required auditor means HOLD; current AUDIT_ONLY remains AUDITOR_NOT_CONNECTED. PACKAGE_COMPLETE does not imply Author Preview PASS.
7. Explicit versioned REUSE policy authorization for the route/artifact/compatibility class. No silent fallback to FULL_SLICE; no printer action or new Print GO.

Every failure -> HOLD/deny with machine-readable reason; no artifact substitution, manifest rewrite or re-slice. A fixture or worker cannot self-approve compatibility/audit/Print GO. Receipt pins are not signatures: trusted provenance and fresh content verification remain required. Mutable/current bytes changing after verification require immutable execution/artifact binding or reverify before use; neither a digest nor mtime proves future stability. These are future gate requirements, **no cache/REUSE implementation** now.
Nondeterminism retained from existing REPRO_AUDIT_01: `same SLICE_KEY ≠ same GCODE_SHA256`. Multiple successful artifacts may share one request key; cache needs separate immutable run/artifact IDs and policy selection, not a single canonical G-code result or byte-determinism claim. SUCCESS ≠ technical PASS ≠ Author Preview PASS ≠ Print GO.

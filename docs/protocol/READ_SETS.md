# Task-specific Read Sets

Apply CORE to repository work once per current task context. Choose the smallest relevant entry below; this is a router, not a checklist to load in full.

| Assignment | Entry | Follow only for a concrete need |
|---|---|---|
| Overall / Team SOL | relevant CURRENT front; active task | evidence for the decision; affected lane dependencies |
| Assigned implementer | lane CURRENT front; bounded task | required contracts, code, fixtures, and validation evidence |
| Research | research task/current; named source packages | explicitly involved repository lanes; required provenance |
| Maintenance | infrastructure task; exact paths and observed state | preservation records and relevant manifests |
| Documentation-only correction | relevant rules and target file context | affected authority/links; a lane CURRENT only when implicated |

`SOL`, `LUNA`, and `Implementation SOL` describe assignments, not automatic model permissions. Research Astra remains Research-only unless explicitly reassigned. HANA, Viewer, ART, SKIN_ABC, and SKIN_R use their own entry in [the lane index](../status/README.md); they do not preload each other.

Use Hikari's dedicated authority gate for Hikari work. `STATEMENT.md`, `RESEARCH.md`, historical tasks, and broad architecture remain available by need. Do not repeatedly reload unchanged material already available in context; refresh authority when resuming, when a revision is reported, or before publishing against it.

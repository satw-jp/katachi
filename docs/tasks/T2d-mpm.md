# T2d — 本物を混ぜる（Study: S2c・MPM）

対象: 実装モデル（モデル非依存）。着手前に STATEMENT → RESEARCH（**v3 の Y5・Y6 を必ず読む**）→
AGENTS → この文書を読む。共通規約は [README.md](README.md)。

## 目的（Y6 が発注）

作者の言葉: 「弾性論や流体力学を取り入れると**僕が考えられないことが入っていって新しい形になる**」。

粗い素描（S2b のバネ・凝集）には作者と実装者が入れたものしか入っていない。
この Study は**本物の連続体力学を形態形成原理として**導入する — MPM（Material Point Method）で
弾性固体〜液体を一つの解法で扱い、しわ・ちぎれ・折り畳みのような
**誰も書き込んでいない振る舞い**が形に入ってくる場所を作る。

**Y6 の役割分離を守る**: これは生成の物理（本物に近づけるほどよい）。
計器（余白の色）は当面この Study に持ち込まなくてよい — 混ぜて濁すより、まず流れる本物を見る。

## 作るもの

### 1. MLS-MPM の核

- 固定時間刻み・固定格子（まず 48³〜64³ 程度）・MLS-MPM（P2G → 格子更新 → G2P）
- **構成則が相のつまみ**: 弾性固体（Neo-Hookean 等の実在の構成則）↔ 液体（弱圧縮流体）を
  パラメータで滑らかに行き来できること。ヤング率・粘性など、**本物の名前を持つ量**で持つ
  （「柔らかさ0..1」の抽象は UI 側の見せ方に留め、内部は物理量。単位と典拠を README に）
- 重力・地面（貫入禁止）。壁はあってもなくてもよい

### 2. 雲との接続

- **種まき**: S1 の雲（球のリスト）を初期材料として粒子化する（球の内部に粒子を撒く）。
  現在の雲を持ち込めること — S1/S2b からの導線は素朴でよい（例: レシピ JSON を読み込む）
- **表示**: 第一段は粒子の点描でよい。余裕があれば粒子→密度場→レイマーチ
  （既存シェーダの流儀）。選択と理由を README に
- **凍らせる**: 流れている材料の一瞬を球のリストに戻して焼き付ける
  （粒子群→クラスタ/密度から球を当てる粗い変換でよい）。凍結結果は S1 形式のレシピとして
  書き出せること — これで S2b・将来の T3（印刷）の世界に還流する

### 3. 履歴と決定性（設計判断済み — 従うこと）

- GPU 並列の浮動小数点は加算順が不定で、**シミュレーション過程のビット単位の再現は保証しない**。
  これは隠さず README と画面の注意書きに明記する
- そのかわり**正本の再現は絶対**: `freeze` は焼き付け結果（球のリスト）を**引数に明示的に持つ**
  （addBall が座標を明示するのと同じ流儀）。履歴の再生はシミュレーションを再実行せず、
  記録された凍結結果を使う — 過程は非決定でも、作品（正本）は完全に再現される
- 履歴に乗る操作: 種まき・物理パラメータ変更・シミュレーション実行区間・freeze。
  形式はこれまでと同じ `[{t, op, args}]`

### 4. 正直さ

- 常設バナー（例:「MLS-MPM による連続体の近似。格子解像度と時間刻みに依存する。
  実物の保証はしない」）。粗い素描ではなくなったが、**近似であることは変わらない** —
  解像度・刻み幅・構成則の名前を画面か README で言えること

## やらないこと

- 計器（余白の色）との統合（次の段 — まず流れる本物を見る）
- 風・気流の場（MPM が入れば風は外力として自然に足せる。この Study では重力のみでよい）
- 印刷用メッシュ出力（T3）。マルチマテリアル・異方性・ケブラー（後の段）
- 60fps の保証（応答性は測って報告する。遅いなら遅いと言う）

## 完了条件

1. 雲（球のリスト）を材料として撒き、重力の下で**弾性固体の端**（形を保って弾む/たわむ）と
   **液体の端**（流れて広がる）の両方が観察できる
2. 相の中間で、**S2b のバネ素描では出なかった振る舞い**が最低一つ観察され、README の
   Observation に日付つきで記録される（例: ちぎれ・折り畳み・しわ・液柱の首締まり）
3. 「凍らせる」で流動の一瞬が球のリストに焼き付き、S1 形式のレシピとして書き出せる。
   そのレシピを S1/S2b で読み込むと同じ形が現れる
4. 履歴の export→import で正本（凍結結果を含む）が完全に再現される
5. 作者の機材のどちらか（まず M4 Mac の Chrome を想定）で動く。粒子数・格子・fps の実測が README にある
6. バナー常設・README（式と構成則の名前・選定理由・実測・既知の限界）・manifest・ビルド通過

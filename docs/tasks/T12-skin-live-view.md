## 作るもの

### 1. 選択ハイライトの修理（バグ）

- 疑い筋: T11 で uPatchData の owner インデックスに形状フラグを端数で畳み込んだため、
  シェーダの `uSelectedPatchOwner` との比較が平リング/立体リングで一致しなくなった。
  floor 比較にする等で修理。**形状ボタン（コイン/平リング/立体リング）の active 表示**も
  選択状態を反映しているか点検し、欠けていれば直す
- 検証: 三形状すべてで、クリック選択 → 画面の該当パッチが青くなる（実座標クリック）

### 2. ビーズ近似表示（インタラクティブな全量ビュー）

- **InstancedMesh の球**で全パッチ点＋ホスト球を描く新表示モード「ビーズ表示」。
  数万インスタンスは GPU が余裕で回す — オービット・ズームは通常の three.js シーンとして
  そのままインタラクティブ
- ブレンド（smooth-min）は省略される近似であることを画面に正直に表示
  （例: 「ビーズ近似: ブレンド省略・配置と密度は全量正確（全 N 点）」）。
  リングは元々数珠なので見た目の乖離は小さいはず — 乖離が出る形状（コインの融合など）は
  README に正直に記録
- **自動切替**: 総点数がレイマーチの容量（PATCH_MAX_POINTS）を超えたら自動でビーズ表示へ
  （黙って先頭だけ描くのを廃止 — あれが「まばらに見える」誤解の源だった）。
  手動トグルも: レイマーチ（容量内のみ）/ ビーズ（常時可）/ 全体メッシュ（既存・重い・正確）
- 選択・クリック追加などの操作がビーズ表示でも機能すること（ピッキングは既存の CPU 側を流用。
  選択パッチのビーズは青く — §1 と同じ選択色）
- ホストは薄い色/半透明のビーズで下敷きに（プレート版で「形態は暗示」の感覚を保つ）

## やらないこと

- レイマーチの容量拡張（テクスチャ渡し等 — 別便）。全体メッシュ表示の高速化
- 他 Study への展開（skin だけ。うまくいったら後で共通化を提案）

# T3（第一便）— 固体として出力する（S1 にメッシュ書き出しを架ける）

対象: 実装モデル（モデル非依存）。着手前に STATEMENT → RESEARCH（Y5 の「固体として出力」が
この任務の発注）→ AGENTS（§3 実座標クリック検証を含む）→ この文書。共通規約は [README.md](README.md)。

## 目的

雲（球のリスト＋ブレンド k = SDF）を**印刷とCADに渡せる 3D データ**にする。
これで全ルートが閉じる: 手でこねた雲（S1）も、たわませ凍らせた形（S2b）も、
MPM で流して凍らせたしぶき（S2c → S1 レシピ還流）も、同じ門から固体になる。

T3 本体（印刷して壊す・突き合わせ記録テンプレート）のうち、この便は**書き出しの橋だけ**。
壊す実験は人間の仕事（AGENTS §6）で、テンプレートは次の便。

## 作るもの

### 1. マーチングキューブス（`src/library/` 候補だが、まず S1 の中に）

- S1 の `fieldSdf`（同じ smooth-min、同じ k）の等値面 0 を三角形メッシュ化する。
  **画面のレイマーチと同じ場の定義を使う** — 見ているものと出力されるものが必ず一致する
- 解像度はつまみ（例 64〜256、既定 128）。ケースは古典的な 256 テーブル（出典を README に）
- 頂点は格子エッジ上で SDF 値の線形補間（角ばりを消す最低限）

### 2. 書き出しダイアログ（S1 のパネルに「3Dデータで書き出す」ボタン）

- **寸法が第一級**: スケッチ単位は抽象なので、書き出し時に**実寸を決めさせる**
  （最長辺の目標 mm、既定 80mm — Bambu A1 のビルドボリュームに収まる手のひらサイズ）。
  出力直前にバウンディングボックス mm・三角形数を表示する（分かって出す）
- 形式: **バイナリ STL**（печатの標準・実装が素朴）と **OBJ**（Rhino/Blender 取り込み用）。
  3MF は後の便（必要になってから）
- ファイル名に日付と由来（例 `yohaku-cloud-20260710.stl`）

### 3. 正直さと記録

- 書き出しは**導出であって手ではない** — 履歴に乗せない（正本を変えないため）。
  ただし書き出したという事実は残したい: 書き出し時に、その時点の**レシピ JSON を同名で
  並べて保存する**ことを促す（ボタン一つで .stl と .recipe.json の二つが落ちる、が理想）。
  印刷物と正本の対応が後から辿れる — S3「印刷して壊す」の突き合わせの前提
- メッシュの水密性（マニフォールド）を検査して結果を表示する。水密でないなら
  正直にそう言う（スライサーで直せることもあるが、黙って渡さない）

## やらないこと

- 3MF・スライサー連携・サポート材の知恵（印刷側の仕事）
- メッシュの後処理（スムージング・簡略化）— 場が正本、メッシュは使い捨ての導出物
- S2b/S2c への直接のボタン設置（S1 レシピ還流で足りる。門は一つ）
- 壊す実験・記録テンプレート（T3 第二便）

## 完了条件

1. S1 で雲をこね、「3Dデータで書き出す」→ 実寸を指定 → STL と OBJ が落ちる
2. 落ちた STL が**水密**で、指定した実寸（最長辺 mm）になっている（検査結果の実測を README に）
3. MPM で凍らせた S1 レシピを S1 に読み込み、同じ手順で STL にできる（相の造形の一周が閉じる）
4. 解像度つまみが効き、三角形数とバウンディングボックスが書き出し前に見える
5. レシピ JSON が STL と対で保存できる（印刷物→正本の遡行可能性）
6. 実座標クリックで UI 全操作を検証。README（アルゴリズム出典・水密検査の方法・実測）・
   manifest 版上げ・revisits・`npm run build` 通過

## 参考（拘束ではない）

- マーチングキューブスのテーブルは Paul Bourke の古典で十分（出典明記）
- バイナリ STL: 80byte ヘッダ + uint32 三角形数 + 三角形×50byte。単純
- 水密検査: 各エッジがちょうど2つの三角形に共有されるか（エッジマニフォールド）

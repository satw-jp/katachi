# T2f — 外の形を招く（Study: S2c v0.3・STL 取り込み）

対象: 実装モデル（モデル非依存）。着手前に STATEMENT → RESEARCH（§3「入口 = 既存メッシュ/NURBS の
SDF 化（過去作を輸入して余白を測る）」がこの任務の予言）→ AGENTS（§3 実座標クリック検証）→ この文書。
共通規約は [README.md](README.md)。**S2c（`src/studies/mpm/`）の版上げ**。

## 目的（作者の言葉 2026-07-10）

「最初の入力のかたちは僕が今まで作った Blender や STL から読み込めるようになると良い」
「作業負荷が一番少ない方法を考えて」

**最小負荷の設計（確定 — 従うこと）**: STL → **MPM の粒子**として撒く。球への変換はしない —
それは既存の「凍らせる」の仕事（粒子→球は freeze が既にやる）。新規実装は
「STL を読む」＋「メッシュの内側を粒子で満たす」の二点だけ。
これで STL → 粒子 → （流す/流さない自由）→ 凍結 → S1 → 編集・STL 再出力の全ルートが
既存機構だけで閉じる。過去作を読み込んで溶かし、途中で凍らせ直すことが最初からできる。

## 作るもの

### 1. STL パーサ（バイナリ必須・ASCII は余裕があれば）

- バイナリ STL: 80byte ヘッダ + uint32 三角形数 + 50byte×三角形。素朴に読む
- ASCII STL はヘッダが "solid" で始まる。判別して対応するか、
  「バイナリで書き出し直してください」と正直に言うか、どちらでもよい（README に明記）
- OBJ は今回やらない（Blender は STL を吐ける。門を増やさない）

### 2. 内側を粒子で満たす（ボクセル充填）

- 取り込み時に**大きさと置き方を正規化**: バウンディングボックスの最長辺を MPM ドメインに
  収まる寸法（既定はドメインの 6 割程度）へ一様スケールし、接地余白を取って地面の上に置く。
  S1 由来の `liftAboveGround` の流儀を踏襲
- 内外判定: 格子点から +X 方向へレイを飛ばし、三角形との交差数の偶奇で内側を判定
  （分岐の少ない古典。交差判定は Möller–Trumbore 等、出典を README に）
- 粒子密度は既存の `particlesPerUnitVolume` に従う。粒子数の上限を守り、
  超えるなら間引いて**画面にそう言う**（黙って欠けさせない — S1 の球数上限の教訓）
- **水密でない STL への正直さ**: 偶奇判定は穴のあるメッシュで誤充填しうる。
  充填結果の粒子数と推定体積を表示し、「変だと思ったら Blender 側で穴を塞いでください」の類の
  注意を README とインポート付近の hint に書く。検査までは作らない（最小負荷）

### 3. 履歴と UI

- 新 op `seedMesh` は**作らない**。充填した粒子の元になる情報を既存の `seed` op に乗せる形を
  検討し、素直に乗らなければ新 op を最小で切る（どちらにせよ **replay で同じ粒子配置が
  再現される**こと。三角形データを履歴に丸ごと入れるとレシピが肥大するので、
  充填後の**粒子座標を引数に持つ**方式を推奨 — freeze が結果を引数に持つのと同じ流儀）
- UI: 「STLを取り込む」ファイル入力を S2c パネルの種まき欄に追加。
  取り込み後は通常の種まきと同じ状態（実行・相・凍結すべて使える）

## やらないこと

- .blend の直接読み込み（Blender から STL エクスポートで足りる）／OBJ・3MF・.3dm
- 球フィッティング・メディアル軸（freeze が既にその役）
- メッシュの修復・簡略化・水密化（Blender 側の仕事）
- S1 への直接インポート（門は MPM の粒子。球が欲しければ凍らせる）

## 完了条件

1. Blender から書き出したバイナリ STL を S2c で取り込み、粒子として現れ、地面の上に正規化配置される
2. そのまま「凍らせる」→ S1 レシピ書き出し → S1 で表示 → STL 再書き出し、の一周が通る
   （外の形が Katachi の正本の世界に入国できた証拠）
3. 相を液体にして流す → 凍らせる、も通る（過去作が溶ける）
4. 履歴 export→import で取り込んだ粒子配置が完全に再現される
5. 粒子数上限の間引きと非水密メッシュの注意が画面/README にある（正直さ）
6. 実座標クリックで UI 検証・README（形式・内外判定の出典・実測: 取り込み時間と粒子数の例）・
   manifest 版上げ・`npm run build` 通過。**既存機能（種まき・凍結・書き出し）の無退行確認**

## 検証用の入力

実 STL が手元に無い場合は、S1 の「3Dデータで書き出す」で作った STL を入力に使えば
自己完結でテストできる（S1 → STL → S2c 取り込み → 凍結 → S1 という往復は、
それ自体が形式の健全性テストになる）。

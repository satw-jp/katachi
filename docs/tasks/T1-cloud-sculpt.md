# T1 — 雲をこねる（Study: S1）

対象: 実装モデル（モデル非依存）。着手前に STATEMENT → RESEARCH → AGENTS → この文書を読む。
共通規約は [README.md](README.md)。

## 目的

場の造形の最小体験を作る。作者がブラウザで**雲の形をこねられる**こと — それだけ。
力・重力・印刷は扱わない（T2/T3）。ただしこの Study が Yohaku の土台になるので、
「場が第一級」「操作は履歴」という二つの背骨だけは最初から正しく敷く。

## 作るもの

`src/studies/cloud-sculpt/` に自己完結の Study 一式。

### 1. 形の場

- 雲 = 球の集まりの滑らかな合成（メタボール）。SDF: 各球の距離場を smooth-min で合成
- 内部表現は「球のリスト（中心・半径）＋合成パラメータ」でよい（これが場の定義になる）
- 表示: レイマーチでもマーチングキューブス→メッシュでもよい。選定理由と、
  こねたときの応答速度の実測を README に残す（AGENTS §5: 応答性とのトレードオフは人間に選ばせる）

### 2. 二つの手

- **つまみ**: 球の数／半径の分布（大小のばらつき）／ブレンドの強さ（smooth-min の k）／
  乱数シード。値はスライダー＋数値表示。UI は素朴でよい（比較 > 装飾）
- **こねる**: マウスで直接介入する。最低限 = クリックで球を足す・選んで消す。
  できれば = ドラッグで球を動かす。カメラはオービット（回して見られること）

### 3. 手の履歴（この Study の一番大事な成果物）

- すべての操作（つまみの変更・球の追加・削除・移動）を**時系列の操作列**として記録する
- JSON で書き出し（ダウンロード）・読み込みができ、**読み込むと同じ形が再現される**
- 形式は素朴でよい: `[{t, op, args}, ...]`。これが「正本 = 場＋手の履歴」（RESEARCH §3）の種になる

### 4. Study の体裁

- `README.md`（Question/Setup/Observation/Hypothesis/Related/Next）。Question は例えば
  「球の集まりは、いつ雲に見え始め、いつ塊に堕ちるか」— 起草してよいが作者の言葉を上書きしない
- `manifest.json`（名前・作成日・パラメータ一覧・revisits）
- 画面に Version と UpdatedAt（ルート共通 UI ルール）

## やらないこと

- 重力・応力・余白の色（T2）。印刷用の出力（T3）。育てる手（T6）
- Library への昇格（昇格は人間の承認事項）
- UI の作り込み・モバイル対応・保存のクラウド化

## 完了条件

1. ブラウザで開き、初見の人間が**3分以内に雲らしい形をこねられる**
2. 操作履歴を書き出し → ページを開き直して読み込み → **同じ形が再現される**
3. つまみを振って「雲に見える／見えない」の境目が観察でき、その一例が README の Observation に日付つきで書かれている
4. ビルドと起動の手順が README に書かれ、その手順どおりに動く
5. 仮決めリストと未解決を完了報告に含める

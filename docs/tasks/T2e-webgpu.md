## 目的

作者の機材（M4 MacBook Air / RTX 3080 Windows、どちらも Chrome の WebGPU 対応）で
MPM を**こねる手応えの速度**に近づける。CPU 実装は実時間の約56倍遅い（README 実測）—
これを WebGPU compute で桁を変える。

## 方針（設計判断済み — 従うこと）

1. **CPU 実装は残す**。役割は二つ: WebGPU 非対応環境のフォールバック＋**検算の基準**
   （同じ種・同じパラメータ・少粒子で CPU と GPU の結果を突き合わせるテストを作る。
   浮動小数の加算順で完全一致はしない — 位置の統計量（重心・広がり・エネルギーの類）が
   許容誤差内で一致すればよい。許容値と根拠を README に）
2. **物理は変えない**。構成則（Neo-Hookean ⇄ 弱圧縮粘性流体）・時間刻み・格子は CPU 版と同一。
   移植であって改造ではない。挙動を変えたくなったら別タスクとして人間に返す
3. **P2G の散布は固定小数点 atomics**（atomicAdd\<i32\>/u32 への固定小数点エンコード）が標準の型。
   別の方法を選ぶなら理由を README に
4. **描画のデータの流れを意識する**: 粒子位置を毎フレーム CPU に読み戻すと転送が速度を食う。
   GPU バッファから直接描く（カスタムレンダパス等）か、読み戻すなら**そのコストを実測して**
   README に書く。「計算は速くなったが表示で全部食われた」を黙って出さない
5. **履歴と正本は不変**: 履歴形式・op は変更しない。GPU の加算順非決定により
   同じ履歴の再生でも粒子状態は僅かに揺れる（T2d §3 で織り込み済み — freeze が結果を
   引数に持つので正本は不変）。バックエンド（CPU/GPU）は履歴に**乗せない**。
   画面には現在のバックエンドを常時表示する（正直さ: どちらで計算しているか隠さない）

## 作るもの

- `src/studies/mpm/` に WebGPU compute バックエンド（WGSL）を追加。起動時に能力検出:
  WebGPU が使えれば GPU、なければ CPU に自動フォールバック（画面にどちらか明示。
  手動切り替えスイッチもあるとよい — 検算と比較のため）
- gridN を UI に出す（T2d の宿題。GPU なら 64〜128 も現実的なはず — 上限は実測で決める）
- 粒子数スケーリングの実測表: 例 3k / 30k / 100k（可能なら 300k）粒子での ms/substep と
  実効 fps を、この Mac（開発機）で計測して README に。作者機（M4/3080）の欄は空けておき
  「作者の実測待ち」と明記

## 検証の注意（AGENTS §3 の改訂を守る — 2026-07-10 の実害から）

- **UI の対話性は実座標クリックか `document.elementFromPoint` で確かめる**。
  合成 `element.click()` はヒットテストを迂回するので不可
- この開発機のヘッドレス検証環境で WebGPU が使えない場合: CPU との検算はユニットテスト
  （核の純関数を Node で回す等）に落とし、GPU パスは「シェーダがコンパイルされ
  パイプラインが作れる」まで確認、実機の絵は作者検証待ちと正直に報告する。
  **その場合も CPU パスの無退行（実座標クリックで全操作）は必ず通す**

## やらないこと

- 物理の変更・新しい力（風は T2f 候補）・余白の色の統合
- three.js の全面置き換え（描画だけ最小限の変更で。他 Study に影響を出さない）
- 60fps の約束（測って報告する。ただし GPU で桁が変わらないなら原因分析を README に）

## 完了条件

1. WebGPU 環境で GPU バックエンドが動き、CPU 比の高速化が実測で示される（同一粒子数の ms/substep 比較）
2. CPU との検算テストが通る（統計量の一致、許容値つき）
3. WebGPU 非対応環境で CPU に自動フォールバックし、全機能が従来どおり動く（実座標クリックで確認）
4. 画面に現在のバックエンドが常時表示される
5. gridN が UI から変えられ、履歴に記録される（既存 op `setParam` のまま）
6. 履歴 export→import・freeze・S1 レシピ書き出しが両バックエンドで機能する。
   README（設計・WGSL の要点・実測表・既知の限界）・manifest 版上げ・`npm run build` 通過

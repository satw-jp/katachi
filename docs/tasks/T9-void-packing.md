## 目的（作者の言葉そのものが仕様）

「ある形態を実体としたときに、内部にできるだけ虚の物体を詰め込んで、
ブーリアン除算したときに残る、元の形態の骨組みのようなものを作りたい」

- **積む単位は虚。作品は残り物。** 詰め方のランダムさ・不完全さが、骨の太さのムラ・
  偶発的な開口・膜と柱の混在を生む — そこが Voronoi 分割（均質で死ぬ）との違い
- 詰め込み密度の**帰結として** 殻に穴 → 膜と柱 → 骨組みだけ、が創発すること。
  遷移をつまみで直接彫らない（それは S-foam で外した道）

## 作るもの

`src/studies/pack/` に自己完結の Study 一式（`pack.html`、ナビリンク、Version/UpdatedAt、
README、manifest）。

### 1. 場の定義（実と虚の二層）

- **実体（ホスト）**: S1 と同じ球のリスト＋k（既定の grow / S1 レシピ読み込み。
  T2f の成果があるので、可能なら STL 取り込み→ホスト化も歓迎だが必須ではない —
  最小は S1 レシピ経由で過去作も入るため）
- **虚**: もう一つの球のリスト（当面は球。歪んだ塊は後の便）
- **合成 SDF**: `max(hostSdf, -voidSdf)` の滑らか版（smooth subtraction — 作者の作品は
  ふわふわした角の丸い引き算。丸さの k をつまみに）。表示はいつものレイマーチ

### 2. 詰める手（この Study の核）

- 「**詰める**」ボタン: ホスト内部にランダムな虚の球を**貪欲パッキング**で追加する
  - ランダム点をホスト内部からサンプル → その点に置ける最大半径 =
    min(サイズ上限, 既存の虚たちとの距離 − 隙間, 表面までの距離 ± 食い込み許容)
  - 半径がサイズ下限を下回る場所は棄却。試行を繰り返し、置けなくなるまで（または上限まで）
- つまみ:
  - **虚の大きさ**（下限・上限 — 大小混ぜるのが作者の流儀。分布は一様でよい、理由を README に）
  - **隙間 g**（虚と虚・虚と表面の間に残す最小の肉 = **骨の最小太さ**。印刷可能性に直結）
  - **食い込み**（虚がホスト表面をどれだけ破ってよいか。0 = 閉じた殻のまま、
    大きくすると表面に開口が生まれる — 穴はここから創発する）
  - **詰め込みの強さ**（試行回数 or 目標充填率）・**シード**
- 履歴: 「詰める」は**結果の虚球リストを引数に持つ**一つの op（`packVoids` —
  freeze と同じ流儀。乱数の再現に依存せず正本が再現される）。個別の虚の削除・
  手動追加（クリックで虚を置く/選んで消す）もできれば望ましい — 詰めた後に
  手で間引くのは作者の自然な手つきのはず

### 3. 計器（正直さ）

- **最薄の肉の推定**を表示: 現在の虚配置で残る骨の最も細い箇所の推定値
  （厳密でなくてよい — 隣接する虚ペア間の実測最小距離。mm 換算も書き出し寸法と連動で）
- 充填率（虚の体積合計 / ホスト体積の粗い推定）を表示 — 「できるだけ」が数字で見える

### 4. 出口

- STL/OBJ 書き出し: S1 の meshExport 機構（`buildMeshFromField`）に合成 SDF を渡す。
  実寸 mm・水密検査・レシピ対保存はいつもどおり
- S1 レシピ書き出しは**できない**（S1 の正本は実の球だけで、虚を表現できない）。
  これはこの Study が初めて正本の語彙を拡張する（実+虚）ことを意味する — README に明記し、
  レシピ形式は独自（`studyId: "pack"`、実球＋虚球＋パラメータ）でよい

## やらないこと

- 虚の形の多様化（歪んだ塊・角柱等 — まず球で骨組みの創発を見る）
- 物理・重力との統合。輪(S-rings)との合成。パッキングの最適化アルゴリズムの追求
  （貪欲で十分。詰め方の偶然こそ価値、と骨子にある）
- 既存 Study の変更

## 完了条件

1. ホスト（既定の雲）に「詰める」→ 虚が貪欲に詰まり、合成 SDF の絵が即座に変わる
2. **食い込み 0**: 閉じた殻＋内部空洞の塊／**食い込みを上げる**: 表面に開口が生まれる／
   **隙間を小さく＋強く詰める**: 骨組みだけが残る — 三つの状態が**パッキングの帰結として**出る
3. 最薄の肉と充填率が表示され、書き出し寸法の mm と連動する
4. STL 書き出しが通り水密（実測を README に。骨が細いときの解像度依存も正直に）
5. 履歴 export→import で実・虚とも完全再現（packVoids が結果を引数に持つ）
6. 実座標クリック検証・既存6ページの無退行・README（パッキングの式・棄却条件・実測）・
   manifest・`npm run build` 通過

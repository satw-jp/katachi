# T11 — リングの皮（Study: S-skin v0.2・輪で総体をつくる）

対象: 実装モデル（モデル非依存）。着手前に STATEMENT → RESEARCH（Y7 系）→ AGENTS（§3）→
この文書 → **S-skin（T10）と S-rings（T8）のコードと README**（この便は両者の合流）。
共通規約は [README.md](README.md)。**S-skin の版上げ**。T10 の既存機能（コイン・窓・反転）を壊さない。

## 目的（作者の言葉 2026-07-13）

「今は実体のときにコインを敷き詰める感じだけど、**リングを敷き詰めたときはリングによって
総体の形状ができるのが見たい**」

コインの点在は分離した部品だった。リングには穴があるので、隣同士が**絡み合える** —
接着なしで布として繋がった皮（鎖帷子）になり得る。総体の形状が「単位の集積」だけでなく
「単位の**連結**」から立ち上がるかを見る。

## 作るもの（S-skin にパッチ形状の切替を追加）

### 1. パッチ形状: コイン / 平リング / 立体リング

- **コイン**: 現状のまま（無変更）
- **平リング（座金）**: 現状のパッチから同心の内孔を抜いた環状プレート。
  つまみ = 内孔率（0=コイン 〜 0.9=細い環）。窓モードでは **O 字型の窓**になる
- **立体リング**: 表面のアンカーに接するトーラス（S-rings の語彙を輸入 —
  節のある球の鎖として作る。節の数・管の太さ・ふわつきのつまみは S-rings と同じ流儀。
  実装は S-rings の輪生成コードの共有を推奨、コピーするなら理由を README に）。
  リングの面はアンカー点の接平面に沿わせる（法線まわりの回転はランダム）

### 2. 絡みの許容と計器（立体リングの眼目）

- パッキングの間隔つまみに**負側**（重なり許容）を持たせる: リング同士が重なって置けると、
  管が隣の孔を通る配置が確率的に生まれる（真の鎖帷子の織りは狙わない — 貪欲配置の偶然でよい。
  それが作者の流儀）
- **絡み計器**: S-rings の Gauss linking number（linking.ts）を流用し、隣接リング対の
  絡み数を集計。**「絡んだペア数 / 隣接ペア数」と連結成分数**（絡みで繋がった群の数）を表示 —
  「布になったか、まだ点在か」が数字で見える
- 深いめり込み（絡みでなく融合）の警告も S-rings と同じ流儀で

### 3. 反転と出口

- 実/虚の反転は形状によらず維持: 立体リングが実（リングの集積が総体をつくる —
  ホストは印刷されない）／ホストが実（表面にリング型の溝/貫通が刻まれる、は平リング窓で）
- STL 書き出し・レシピ（結果を引数に持つ op）・計器の mm 連動は T10 の流儀のまま

## やらないこと

- 物理による織り・編み（幾何配置の偶然だけ。物理で編むのは MPM 統合後の遠い便）
- 平リング/立体リングの個別ドラッグ（T10 と同じく手動追加・削除まで）
- 既存 T10 機能・他 Study の変更

## 完了条件

1. パッチ形状の切替（コイン/平リング/立体リング）が動き、T10 の既存動作が無退行
2. 平リング: 内孔率つまみが効き、窓モードで O 字の窓が出る
3. 立体リング: 表面に接して詰まり、**リングだけでホストの総体形状が読める**
   （ホスト表示 off でも形が立ち上がる — スクリーンショットで確認）
4. 重なり許容で絡んだペアが生まれ、**絡み計器**（絡んだペア数・連結成分数）が正しく出る
   （既知の配置での検証を含む）
5. STL 書き出し（立体リング版の水密実測）・履歴 export→import 完全再現
6. 実座標クリック検証・既存8ページ無退行・README（式・実測・鎖帷子がどこまで出たかの正直な観察）・
   manifest 版上げ・`npm run build` 通過
